Why a rule in the prompt is a request, not a control

What goes wrong without a code gate

Put the rule only in the system prompt and it holds most of the time. Most of the time is not a control: you cannot write a test for it, and you cannot describe it to a risk committee.

Why that happens

A system prompt is text competing with other text — the user's phrasing, the tool results, the model's own earlier reasoning. It has influence, not authority.

Prompt rule

Probabilistic · untestable · drifts when you reword for tone · invisible in audit

Code gate

Deterministic · unit-testable · survives prompt edits · logged every time it fires

Real scenario

Delete the code gate in Lab 1B, keep the prompt rule, and run the compensation request several times. It usually refuses. The run where it does not is a £120 payment with no approval and no record that a rule existed.

Keep both. The prompt tells the model the boundary exists so it can explain the refusal. The code makes the boundary real.

If the audience takes one idea out of Session 1, make it this one. The framing that lands with engineers: a system prompt is an input, not a configuration. It sits in the same context window as the user's message and the tool output, all competing for influence. Sometimes the user's phrasing is more persuasive than your instruction. That is not a bug to be prompted away — it is what a language model is. Run the demonstration if you have the time; it is more convincing than the slide. Remove the gate, keep the prompt, ask for a full refund plus compensation for the inconvenience, five times. Most runs refuse. Count the one that does not, and ask the room what the post-incident review would say about a control that was written in prose. The closing line matters and people miss it: this is not prompt versus code. You want both. Without the prompt, the model does not know why it was blocked and produces a confused answer. Without the code, there is no block. Likely question: "What about newer, better-aligned models?" Better models follow instructions more often.
