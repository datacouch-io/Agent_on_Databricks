Production agents — the practices that matter

Do

Security: least-privilege service principals; grants not code checks; read-only identities for retrieval.

Governance: tools as Unity Catalog functions; rules at the data; traces in a catalog you own.

Reliability: bounded loops; gates on arguments; idempotent actions; failures the model can read.

Cost: tokens per resolved request; rate limits at the gateway; retrieval tuned before models swapped.

Quality: a fixed evaluation set with negative cases; read rationales; segment before you celebrate.

Operations: aliases set before promotion; canaries with a control; a stated freshness target.

Don't

Don't run production on a personal token. It inherits everything and audits to the wrong person.

Don't ship an aggregate. Read the per-case results, every time.

Don't let a tool return unbounded data. It is a cost, latency and quality failure at once.

Don't treat a client-side check as a control. MCP means the client is a variable.

Don't promote without @previous set, and without having rehearsed the rollback.

Don't assume green dashboards mean good answers. Status measures plumbing.

Every line on the left is something this course built and ran, not a maxim. If you adopt one thing from the right-hand column, make it the last: every span can be OK, every tool can succeed, every latency can be healthy, and the answer can still be wrong.

This is the outline's production best practices bullet, organised by the five concerns a review board will actually raise: security, governance, reliability, cost, quality, operations. Do not read the lists. Pick the two or three that match the room — if there are security people present, work the first two; if it is a platform team, work reliability and operations. The callout is the closing argument and it is the one to say with emphasis. The last "don't" is the sentence that connects every session: status measures plumbing. Spans can all be OK, tools can all succeed, latency can look healthy, and the answer can be wrong — because none of those instruments measures whether the answer was right. That is the gap Session 6 exists to fill and the reason Session 6 then spends forty minutes explaining why those instruments need checking too.
