Why identity-filtered discovery beats a refusal

What goes wrong with a refusal

If the tool is visible and the agent is told not to use it, you have created a negotiation. The model knows a refund capability exists, the user is insistent, and the only thing between them is a sentence in a prompt. Even when it holds, you get apologetic answers about things the user cannot have.

The engineering value

An absent tool cannot be argued for. The model has no knowledge of it, produces no reference to it, and degrades to the capability it actually has.

Visible + forbidden

A prompt rule, a possible leak of internal capability, and a worse answer.

Absent

No mention, no attempt, no negotiation. The agent explains what it can do.

Operationally

Capability changes are grants, not deployments. Revoke and it is gone everywhere.

Real scenario

The restricted agent in Lab 5B is asked for a refund. It looks up the order, quotes the policy, and says a colleague will handle the payment. That is not a blocked agent — it is a correctly scoped one, and the user gets a useful answer.

Session 1 said a prompt rule is a request. This is the strongest version of the same idea: the best control is one the model cannot perceive.

This slide argues for a design choice people often get backwards, so give it the time. The instinct is to expose everything and constrain by instruction, because it keeps one configuration for all users. What that produces is an agent with knowledge of capabilities it may not use, which leaks in two ways: it mentions them, and it can be talked toward them. Filtered discovery removes the category. The model is not resisting temptation; there is nothing there. That also makes the agent's answers better, which is the part teams do not anticipate — an agent that knows it has two tools gives a clean answer within two tools, rather than an apologetic one about a third. The scenario is the one to emphasise because it reframes "restricted" as "scoped". The restricted agent is genuinely useful: it identifies the order, quotes the applicable policy, and routes the payment to a human. Most support interactions should end that way regardless of permissions. The closing line is the sharpest formulation of the course's control theme, and it belongs here at the end of Session 5. Likely question: "How do I test an agent across identities?" Run your evaluation suite once per identity. The right behaviour for a restricted principal is a graceful handoff, and that is a scoreable outcome — which is Session 6. Timing: 4 minutes.
