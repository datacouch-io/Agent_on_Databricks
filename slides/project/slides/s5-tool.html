Lab 5A. The slide to linger on is the middle column, because each row is a thing you used to do in Python and now do in DDL. Take the COMMENT row seriously. That string is what the model reads when deciding whether this tool is the right one. A vague comment produces a tool the model never picks, or picks for the wrong question. You are writing prompt text inside a CREATE FUNCTION statement, and it belongs in code review like any other prompt. Then MCP. There is nothing to build. Point an MCP client at /api/2.0/mcp/functions/your_catalog/your_schema and the functions in that schema are tools. Any MCP-speaking client — including ones written by people who have never heard of your project. Which is exactly why the GRANT row has the red border. The moment your tools are discoverable by clients you did not write, a permission check in your agent code is not a control. The gotcha is real and worth repeating: Unity Catalog wants the application ID. We had two service principals with the same display name, and the friendly name resolved to nothing. Expected question: "What about tools that are not SQL?" Register them as Python functions in UC, or front them with a serving endpoint. The governance story is the same; only the body changes. Timing: 6 minutes.
