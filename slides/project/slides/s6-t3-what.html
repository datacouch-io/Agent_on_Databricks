What is Model Serving for agents?

Model Serving hosts your agent as an HTTP endpoint. You log the agent as an MLflow model, register it in Unity Catalog, and deploy that version — after which anything that can make a request can use it.

ResponsesAgent

The MLflow interface your agent implements so it can be logged and served.

Log and register

Logged as an MLflow model, registered under a three-level catalog name.

Deploy

agents.deploy() creates the endpoint and a review app alongside it.

Premium feature

Model Serving is not available on a trial workspace.

What you get besides a URL

A review app for human feedback, request logging into tables, scale-to-zero, and authentication through the same identities as everything else.

The analogy

The difference between a recipe and a restaurant. Same dish; one of them has opening hours, a queue and health inspections.

Define the three steps clearly because people conflate them: logging captures the agent and its dependencies as an MLflow model, registering gives that model a name and a version in Unity Catalog, deploying puts a specific version behind an endpoint. Three distinct things, and rollback in a moment depends on their being distinct. ResponsesAgent is the interface to name properly. It is the shape MLflow expects — a predict method over a request and response schema — and implementing it is what makes your agent loggable and servable. It is a wrapper around the loop from Session 1, not a rewrite. The white panel is the part that sells it internally. You are not just getting a URL. You get a review app where domain experts can give structured feedback, request and response logging into tables you can query, scale-to-zero so idle costs nothing, and authentication through the same principals as Session 5. Flag the trial limitation plainly, since it is in the pre-flight slide too: on a trial workspace agents.deploy() fails. That is a decision to make before the cohort starts. Likely question: "Can I serve an agent that calls other endpoints?" Yes, and you must pass the resources it depends on at log time so the endpoint is granted access to them.
