Session 1 — AI Agent Architecture and Design

Answers

1A, 2B, 3C, 4D  — and why the others fail.

1

A — Workflow — the sequence of steps is known before you see the data

You know the steps before you see the data: read, extract, write. Varying layouts is an extractor problem, not a control-flow problem.

Calling it an agent because the layouts vary, or because a language model is involved, is the exact bias Lab 1A exists to correct. The claim that agents cannot read PDFs is simply false.

2

B — The model composed an amount above 50: a full refund plus compensation

The customer asked for a refund plus compensation. The arithmetic that mattered happened in args, not in the order record — and args crossed 50.

Calling it a bug inverts the lesson: a gate reading the order total would have let the larger payment through unapproved. Gate on the value being committed, not the value you expect it to be derived from.

3

C — It bounds worst-case cost and latency — an agent that cannot find an answer never gives up

Worst case = MAX_STEPS × tokens per step: a number you can put in a budget, set a timeout on, and alert on.

The model decides what to do next; you keep the decision about how long it may keep going. That separation is the whole point. Improving tool choice is description work, not a stopping condition.

4

D — A code gate on the action, least privilege on the tools, and a human before anything irreversible

An injection is only valuable if the agent can do something. An agent that cannot issue refunds cannot be injected into issuing one.

A system-prompt rule is a sentence competing with every other sentence in the window: it raises the bar and sets no floor, and you cannot write a test that proves it holds.
