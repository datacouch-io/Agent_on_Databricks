Why a managed assistant inherits your data, not your controls

What goes wrong

You spent Session 3 building a governed index with an audience column, and your retriever filtered on it. A managed assistant reads the same index. It was never told about the filter, because the filter was an argument your code passed — not a property of the index.

The engineering value of knowing this

It is the same inheritance test from Session 4, now applied to a product you did not write. If a new client appeared tomorrow, would your rule still hold? For a caller-side filter, the answer is no.

What is inherited

Unity Catalog grants. The assistant cannot read an index it has no access to.

What is not

Your query-time filters, your score floors, your prompt-level caveats.

The fix

Move the rule into the data: separate indexes per audience, or a UC function every caller must use.

This is not a product defect

Agent Bricks is behaving correctly — it is retrieving from an index it has been granted. The defect is in where we put the control. Any client reading that index would do the same.

Set the frame carefully before the demonstration, because it would be easy and wrong to leave the room thinking Agent Bricks is unsafe. The assistant is granted access to an index and retrieves from it. That is exactly what it is for and exactly what it was permitted to do. Nothing is broken in the product. What is broken is our assumption that an audience filter written in our retriever protected the index rather than protecting our calls. Then apply the test from Session 4 out loud: if someone else wrote a new client for this data tomorrow, would the rule still hold? For the audience filter, no. It was a convention, and conventions are properties of the code that honours them. The middle panel is the practical summary. Grants are inherited, because they are platform state. Query-time filters, score floors and prompt caveats are not, because they are caller behaviour. Give the fix so people leave with an action: separate indexes per audience, so access is a grant, or a Unity Catalog function that applies the filter and is the only thing granted. Both move the control to where the data is. Likely question: "Could I have known this in advance?" Yes — by asking the inheritance question when you wrote the filter. That is the habit this course is trying to build. Timing: 4 minutes.
