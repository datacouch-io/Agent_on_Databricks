Why one platform changes what an agent can be trusted with

What goes wrong across separate systems

The warehouse knows who may see a table. The vector database does not. The tracing service holds the answer but not the permission that produced it. Every question an auditor asks spans three products and a spreadsheet, and the answer is assembled by hand.

The engineering value

The table, the index, the tool, the model and the trace are all Unity Catalog objects. One permission model and one lineage graph covering retrieval, action and audit.

Lineage

The index knows its source table; the trace knows which document grounded the answer.

Access

Revoke a table and the agent's retrieval narrows with it. No agent code involved.

Audit

Traces land in a catalog you own, as a table — not a vendor dashboard with an export button.

Real scenario

“Which internal documents reached customer-facing answers last quarter?” With traces in Unity Catalog that is one query joining spans to document ids. Across separate products it is three export requests and a spreadsheet nobody will certify.

Be honest about the trade: you accept a platform dependency. Session 2's seam is the mitigation — your agent logic stays portable even when your governance does not.
