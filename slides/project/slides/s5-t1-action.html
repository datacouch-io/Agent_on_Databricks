See it in action: create, grant, call

-- the tool
CREATE OR REPLACE FUNCTION
  main.agents.get_order(
    order_id STRING
      COMMENT 'Order id, e.g. ORD-1042')
RETURNS TABLE (status STRING,
                total DOUBLE)
COMMENT 'Look up one order by id.'
RETURN SELECT status, total
       FROM main.retail.orders
      WHERE order_id = get_order.order_id;

-- the permission
GRANT EXECUTE ON FUNCTION
  main.agents.get_order
  TO `c3f1...-application-id`;

# the agent side
from unitycatalog.ai.core.databricks \
    import DatabricksFunctionClient

c = DatabricksFunctionClient()
c.get_function("main.agents.get_order")
# -> schema + description, ready

The gotcha that cost us twenty minutes

PRINCIPAL_DOES_NOT_EXIST: Could not find principal with name agents-labs-restricted. Unity Catalog wants the application ID, not the display name — and two of our service principals shared that name.

Expected output

get_order('ORD-1042') → one row: delivered, 38.0. The agent never saw the orders table, and has no SELECT on it.

Two cells and a grant. Walk the left block first and point at the three mappings as you go: the parameter COMMENT is the argument description the model reads, the function COMMENT is the tool description, and the RETURNS TABLE clause is the output contract. Then the grant, and the gotcha. PRINCIPAL_DOES_NOT_EXIST with a name you can see in the admin console is a confusing error. Unity Catalog resolves service principals by application ID, and we had two principals sharing a display name, so the friendly name resolved to nothing. Use the application ID and the problem disappears. Worth thirty seconds because it will happen to someone in the room. The right-hand panel is the payoff. The agent called a function and received one row. It has no SELECT on the orders table and cannot get one by asking differently. Least privilege, expressed as a function signature rather than as application logic. The DatabricksFunctionClient line matters for the next topic: it reads the catalog and produces the tool schema. You do not hand-write the JSON any more — the catalog is the source. Likely question: "What if I change the function?" Callers pick up the new signature and description. That is a feature and a risk: a comment edit changes model behaviour, so review it like a prompt change. Timing: 20 minutes of lab, 4 minutes on this slide.
