What is context engineering in a Databricks agent?

Session 1 covered the principle. Here it is as platform decisions: where state lives, what the agent is grounded in, and which governed object supplies it.

Conversation state

The messages list, inside the serving endpoint for one request. Multi-turn state is yours to carry.

Grounded context

Retrieved from AI Search, returned by a Unity Catalog function, or answered by a Genie Agent.

Semantic context

Metric views, Pages and the Genie Ontology — definitions the agent inherits without being told.

Long-term memory

A Delta table you write to and retrieve from. There is no hidden store.

Config

Model, MAX_STEPS, top-k, thresholds — logged with the model version.

The platform-specific insight

Three of those five are governed objects. Context is not only a token budget here — it is a set of permissions, and the agent's context narrows automatically when a grant is revoked.

The analogy

A briefing note assembled from filing cabinets the reader has keys to. The note is shorter for someone with fewer keys — and correctly so.

The outline asks for context engineering and memory specifically in a Databricks agent, and the platform answer is genuinely different from the generic one. Walk the five rows as five places state can live. The first is familiar from Session 1. The interesting observation is the white panel: three of the five are governed objects, which means the agent's available context is a function of its identity. Say that consequence plainly, because it is not obvious and it is the reason this topic sits in Session 5 rather than Session 1. Revoke a grant and the agent's context shrinks — automatically, with no code change and no redeploy. Context engineering and access control stop being separate disciplines. The long-term memory row is worth a caution. There is no hidden memory store on the platform. If you want an agent to remember a customer's preferences across conversations, that is a Delta table you write to and retrieve from — which makes it a governed object too, with the retention and privacy obligations that implies. The config row connects to Session 6: log it with the model version, or you cannot attribute an evaluation result to it. Likely question: "Does a serving endpoint keep conversation state between requests?" Treat it as stateless. Carry the conversation in the request, or persist it yourself. Timing: 4 minutes.
