Two screenshots that show something the architecture slides cannot: curation is conversational, and it starts from a failure. The first one matters more than it looks. Create Agent appears in the overflow menu under an answer — so the workflow is: someone asks a real question, the answer is wrong or ungrounded, and you turn that moment into a configured agent. That is a much better path than opening an empty configuration page and trying to imagine what people will ask. The second shows Genie One editing a Genie Agent's context during a conversation and reporting what it changed. Useful, and worth a caution: a context edit changes behaviour for every future caller, which makes it a production change with a chat interface. Treat it as a prompt change, because it is one. Hence the third panel. Author in the console, keep the source of truth in a repository, apply through the API. If an instruction governs a number that appears in a board pack, it deserves review and history. Likely question: "Can two people curate the same agent?" Yes, and that is exactly why benchmarks exist — so a second curator can change something and see what they affected. Timing: 3 minutes.
