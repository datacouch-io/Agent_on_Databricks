What is agent identity?

An agent acts as a principal — either a service principal (a non-human identity you create and grant) or, with on-behalf-of-user authentication, the signed-in person.

Service principal

A machine identity. Owns its own grants. Right for automated, unattended flows.

Application ID

Its real identifier in Unity Catalog. Display names are not unique.

On-behalf-of-user

The agent acts as the person asking, and sees exactly their tools and data.

Least privilege

Give the principal the smallest tool set that lets it do its job.

The question identity answers

Not “what should this agent be allowed to do” in the abstract, but “what may this caller, right now, do with this data” — answered by the same system that answers it for your analysts.

The analogy

A staff pass. The same building, the same doors, and what opens depends on the badge rather than on who asks nicely.

Keep this crisp — it is scaffolding for the next two slides, where the demonstration lives. The distinction that matters in practice is between the two models. A service principal is a fixed machine identity with its own grants: right for scheduled work, batch flows, and anything running without a person present. On-behalf-of-user means the agent borrows the caller's identity, so two people asking the same internal assistant get answers scoped to what each may see. For an employee-facing assistant that is almost always the correct choice, and it removes an entire category of data-leak design problem. Repeat the application ID point from earlier. It is the practical trap: display names are not unique and Unity Catalog resolves by application ID. The white panel is the framing to leave them with. Agent permissions are not a new problem needing a new system. It is the same question your warehouse already answers for analysts, asked by a different kind of caller. Likely question: "Can one agent switch between the two?" The deployment decides. Keep them separate — a service-principal agent and an on-behalf-of-user agent have different threat models and should not share a configuration. Timing: 3 minutes.
