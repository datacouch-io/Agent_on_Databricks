Why grounding in governed context beats grounding in a prompt

What goes wrong

Teams paste business context into the system prompt — definitions, table descriptions, caveats, a list of acronyms. It works, and it is paid for on every turn of every conversation, it drifts from the warehouse the week after it is written, and no reviewer sees it change.

The engineering value

A metric view, a Page or a Genie Agent is retrieved when relevant, versioned, owned and permission-gated. You pay for what the question needs, and the definition cannot silently diverge from the data.

Cost

Retrieved context is paid per relevant question. Prompt context is paid per turn, forever.

Freshness

A governed object changes once. A pasted paragraph changes in however many repositories hold it.

Access

Retrieved context respects permissions. A system prompt shows everyone the same thing.

Real scenario

An agent's prompt carries three paragraphs of table descriptions. A column is renamed. The warehouse, the dashboards and the metric views all move together; the prompt does not, and the agent keeps confidently describing a column that no longer exists.

Same rule as everywhere in this course: put the knowledge where the data is, and every caller inherits it — including the ones written after you leave.

This is the context-engineering lesson and the control lesson arriving at the same conclusion, which is a good moment to point out that they are the same lesson. The first panel describes something nearly every team does, and it works at first. Pasting business context into a system prompt is the fastest way to make an agent sound informed. The three costs arrive later and separately: you pay per turn forever, the text drifts from the warehouse, and nobody reviews a prompt the way they review a schema change. The scenario is the clean version. A column is renamed. Everything governed moves together — the tables, the metric views, the dashboards. The paragraph in the prompt does not, because it lives in a repository that nobody connected to the migration. The agent keeps describing a column that is gone, fluently. The access panel is the one that will interest security people. A system prompt is the same for every caller by construction. Retrieved context is gated per identity. If your agent serves people with different entitlements, prompt-pasted context is a design flaw, not an optimisation. Likely question: "Surely some things belong in the prompt?" Yes — role, tone, refusal behaviour, how to explain a gate. Stable instructions about behaviour. Not facts about data. Timing: 4 minutes.
