What is the agent execution loop?

The execution loop is the cycle that asks the model what to do, does it, hands back the result, and asks again — until the model answers in words instead of actions.

Instructions

The system prompt. Role, tone, and what the agent is for.

Tools

Functions the model may request, described by a JSON schema.

State

The growing messages list. Every tool result is appended to it.

Stopping condition

No tool calls returned, or MAX_STEPS reached. Yours, not the model's.

Two kinds of turn

The model returns either text for the user or one or more tool calls. Text means stop. Tool calls mean go round again.

The analogy

A phone call with a colleague who keeps putting you on hold to look something up. The call ends when they finally answer.

Everything a framework does for you later is a wrapper around this loop. Build the mental model now and the frameworks become legible rather than magical. The key structural fact is the fork: a model turn produces either natural language or a request to call tools. That single branch is the entire control structure of an agent. People expect something more elaborate and are often disappointed; the disappointment is the lesson. State deserves a sentence of its own. The messages list is the agent's whole memory of this interaction, and tool results go into it as messages. That is why a tool that returns a fifty-thousand-row table will break your agent — not because the tool failed, but because you just put fifty thousand rows into the next prompt. Analogy: a phone call with a colleague who keeps saying "hold on, let me look that up". Each hold is a tool call. The call ends when they answer instead of holding. Likely question: "Where does the model's reasoning live?" In the conversation, as assistant messages.
