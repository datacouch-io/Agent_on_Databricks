What is an AI agent?

An AI agent is a program in which a language model decides what to do next, in a loop, until a stopping condition is met.

LLM call

LLM = Large Language Model. One request, one answer. No memory, no actions.

Workflow

A sequence of steps you wrote. The model may appear in a step; it never chooses the next one.

RAG

RAG = Retrieval-Augmented Generation. One specific workflow: retrieve, then generate.

Agent

The model picks the step. Order, count and whether to stop are all decided at runtime.

The analogy

A workflow is a recipe. An agent is a cook who tastes and adjusts. Both can produce dinner. Only one of them can be audited in advance.

Four words get used interchangeably in this field and should not be. Spend two minutes separating them, because every architecture mistake in the rest of the course starts here. Read the definition slowly and stress the three words that carry it: decides what next. Not "uses a language model" — a workflow can use a language model in every step and still be a workflow. Not "is conversational" — a chatbot with a fixed retrieve-then-answer path is RAG. Analogy to use: a recipe versus a cook. A recipe is a workflow; you can read it start to finish before you turn on the hob, and you know exactly what it will do. A cook tastes the sauce and decides to add salt. More capable, and you cannot write down in advance what they will do. Define the acronyms as you go — LLM and RAG are both on the slide for a reason. Assume someone in the room has not written one of these before. Likely question: "Isn't an agent just RAG with more steps?" No. RAG has a fixed shape: one retrieval, one generation. An agent might retrieve three times, call a database, decide the question is unanswerable and stop. The shape is a runtime outcome, not a design. Timing: 3 minutes.
