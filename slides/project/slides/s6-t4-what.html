What are model aliases?

An alias is a movable name pointing at one registered model version — @champion, @challenger, @previous. Clients reference the alias; you move it.

@champion

The version currently serving production traffic.

@challenger

The candidate being compared against it.

@previous

The last known-good version. Set it before you promote, not after.

Movable

Reassigning an alias is a metadata change. No rebuild, no redeploy of the artefact.

Why not just use version numbers?

Because then every client has to be updated to change what is live. An alias is a single point of indirection, so promotion and rollback are one operation rather than a coordination exercise.

The analogy

A railway points lever. The trains and the track are unchanged; you are redirecting which way traffic goes, and you can throw it back.

Short slide, one idea: indirection. Explain the problem aliases solve by describing the alternative. Without them, clients reference version 7. To ship version 8 you update every client, in the right order, and to go back you do it again under pressure. With aliases, clients reference @champion and promotion is moving a label. The third card is the operational practice people skip and regret. Set @previous to the current champion before you promote the challenger. Doing it afterwards means that in the moment you need a rollback target, you are working out which version was good from a deployment history — exactly when you least want to be reasoning carefully. The points-lever analogy carries it: the track and the trains do not change, you redirect traffic, and the lever goes back. Likely question: "Is an alias the same as a traffic split?" No, and the distinction matters for Session 7. An alias points at one version. A traffic split sends a percentage of requests to each of two versions. Canaries use both — a split to test, an alias to make the result permanent. Timing: 3 minutes.
