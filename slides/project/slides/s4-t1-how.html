How a Genie Agent answers a question

1 · Question

plain English from a person or an agent

2 · Context assembled

schemas, instructions and examples from the space

3 · SQL generated

scoped to the space's tables only

4 · Executed

on your SQL warehouse, under UC permissions

5 · Rows plus the query

the answer, and how it was obtained

Step 2 is where curation pays

Everything you wrote in the Knowledge Store is assembled into the context for this question. Rules you did not write are rules the model will guess.

Step 4 is where governance holds

The query runs as the caller. If they cannot see a table, no instruction in the space grants it to them.

Step 5 is why it is auditable

You get the SQL. A reviewer can check the join, the filter and the date range without trusting the narrative.

Conversational, with state

Follow-up questions keep context, so “and by region?” works.

The same path for an agent

An agent asking over the REST API traverses these identical five steps.

Five boxes, and the useful observation is that steps two, four and five each answer a different stakeholder's objection. Step two answers the data team: your definitions are in the context, so the model is not inventing them. And the corollary, which is the sentence to say slowly — a rule you did not write is a rule the model will guess at, and it guesses fluently. Step four answers security: the query executes as the caller against Unity Catalog. A space cannot widen anyone's access. If an agent's service principal cannot read a table, pointing a space at that table changes nothing for it. Step five answers audit and it is the feature that makes this usable in a regulated setting. You are not asked to trust a sentence; you can read the query. The last dark panel is the setup for Lab 4B. An agent calling over REST goes through exactly these steps — which is why it inherits the curation without being told about it. Likely question: "Does it ever write SQL that fails?" Yes, and it retries and reports. Persistent failures on a question type usually mean a missing example rather than a model limitation.
