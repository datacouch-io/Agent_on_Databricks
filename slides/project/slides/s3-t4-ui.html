Put both views up together, because the division of labour between them is the lesson. The left-hand view is a single trace. The span tree shows the agent span, the tool spans inside it, the retriever span and what it returned, with inputs, outputs and any assessments attached. This is what you open when someone reports a bad answer, and it resolves the four-way ambiguity from the previous topic in about thirty seconds. The right-hand view is the list. Every interaction, filterable, and — importantly for Session 6 — selectable, so you can pick traces and run scorers over them directly from the UI. The third panel is the one people miss. These views are reading the trace tables. Anything visible here is available in SQL, which is how you get from "this one interaction" to "what is true of this system". Show the UI to earn attention; teach the query. Likely question: "Do I need the UI at all if I have the tables?" For a single bad answer, yes — the span tree is far faster to read than a join. Use both, for different questions. Timing: 3 minutes.
