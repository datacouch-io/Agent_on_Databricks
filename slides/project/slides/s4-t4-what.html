What is calling Genie from an agent?

The agent gets one tool: ask the Genie Agent a question in English. The Genie Agent writes and runs the SQL; your agent receives rows.

The tool

ask_genie(question). No SQL in the agent, no schema in the prompt.

REST under the hood

start-conversation, then poll until COMPLETED, then read the attachment.

Rows come back

The agent reasons over the result, and can ask a follow-up.

No .genie on serverless

The WorkspaceClient has no genie attribute there. The lab calls REST directly.

Why this is a good tool boundary

The agent asks business questions. It cannot write arbitrary SQL, cannot reach tables outside the space, and cannot bypass the curation. Capability without the blast radius.

The analogy

Giving the agent a phone line to the analytics team, rather than a login to the warehouse.

Short definitional slide, and the tool-boundary point in the white panel is the reason it exists. Compare two designs out loud. One: give the agent a run_sql tool. Powerful, and it can now write any query against anything its principal can read, with no business rules applied. Two: give it a Genie Agent as its only data tool. It asks questions in English and the Genie Agent decides what SQL that means, within tables someone chose, with rules someone wrote. The second is less powerful and far more defensible, and it is the right default for an agent facing customers or staff. Capability without the blast radius. The serverless note is on the slide because it cost us time. The Databricks SDK's WorkspaceClient does not expose a genie attribute on serverless compute, so the lab calls the REST endpoints directly — start a conversation, poll until the message status is COMPLETED, then read the query result from the attachment. It is a dozen lines, it is in the notebook, and it works everywhere. Analogy: a phone line to the analytics team, not a warehouse login. Likely question: "Is polling not fragile?" It is the documented pattern; the lab wraps it with a timeout and surfaces the failure as a tool error the model can report rather than hanging. Timing: 3 minutes.
