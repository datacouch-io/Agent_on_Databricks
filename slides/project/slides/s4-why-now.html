Session 3 → Session 4

Why Genie, and why now?

Three sessions built an agent that can read your prose. Here is what you already have — and the question it still cannot answer.

The loop

Bounded, with tools described as schemas and a gate that reads the argument the model composed.

The seam

One retrieval interface, two sources behind it, and an adapter so the same agent runs in four places.

The grounding

A governed index in Unity Catalog, and traces you can query as an ordinary table.

What none of it answers

“What was revenue last month?” is not a document lookup. It is SQL over governed tables, and it needs rules that appear nowhere in your prose — which status means the order never happened, which rows are test accounts.

The build-it-yourself path

A schema in a prompt writes plausible SQL and knows no business rules. Everything you would add next — scope limits, definitions, examples, a regression suite — is what this session is about.

Same boundary, second half

Genie is not a second agent framework. It is the structured half of the agent you already built — same catalog, same grants, same lineage. This session curates it; Session 5 calls it as a single tool.

This slide exists because the jump into Genie reads as a change of subject if you do not frame it. Say the shape of the course out loud: Sessions 1 and 2 built the agent, Session 3 grounded it in documents. Everything so far retrieves prose. Genie is the other half of retrieval - the structured half - and it is not a different platform, it is the same Unity Catalog boundary from Session 3. The honest framing is the second panel. Nobody needs convincing that text-to-SQL is possible; they need to see that the hard part is curation, and that curation needs somewhere governed to live. That is the whole session in one sentence. Expected question: "Could we just give the agent a run_sql tool?" You could, and Session 5 shows what that costs - the rule then lives in your caller instead of at the data, and the next caller inherits nothing. Timing: 3 minutes. It is a bridge, not a topic.
