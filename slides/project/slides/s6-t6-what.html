What is latency engineering for agents?

Agent latency is not one number. It is time to first token, time per step, and the number of steps — and users experience the three differently.

Time to first token

Grows with input length. The user's experience of “is it working?”

Per-step time

Model generation plus tool execution. Tools are often the slower half.

Step count

The multiplier. Two steps instead of four halves the wait.

Perceived latency

Streaming changes this without changing any of the above.

Why the breakdown matters

A p95 of eleven seconds tells you nothing actionable. “Nine of those eleven are one slow tool” is a ticket somebody can pick up.

The analogy

A delayed journey. Knowing it took two hours is useless; knowing ninety minutes were spent at one junction is a plan.

The outline asks for latency challenges and how to reduce them, and the first move is to stop treating latency as a scalar. Break it into three measurable things. Time to first token is dominated by input length, which ties straight back to the context work — a bloated prompt is a slow prompt before any generation happens. Per-step time is generation plus tool execution, and the tool is frequently the slower half, which surprises people who assume the model is the bottleneck. Step count multiplies everything.
