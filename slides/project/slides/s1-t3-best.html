Session 1 — best practices and the mistakes to avoid

Do

Default to a workflow. Promote to an agent when the control flow must be decided at runtime.

Gate on the argument the model composed, not on the value you expect it to be derived from.

Set MAX_STEPS and alert when runs approach it.

Write the rule twice — in the prompt for explanation, in code for enforcement.

Return small, decided answers from tools; they become the next prompt.

Retry transient failures only. Bad arguments will fail identically.

Don't

Don't infer “agent” from “uses an LLM”. A workflow may call a model in every step.

Don't rely on the system prompt for anything you would have to defend in an audit.

Don't gate on context — a gate reading the order total would have passed a £120 payment.

Don't give an agent a tool you would not let it call unattended at 3am.

Don't let a tool return a raw result set. Fifty thousand rows is a silent failure.

Don't ship an unbounded loop and plan to add the ceiling later.

Two of these came from bugs we hit building this course, not from a style guide. The £38 refund that tripped a £50 gate is the one worth re-reading — it was correct, and the reason it was correct is the whole argument for gating on arguments.

Gate on the argument, not the context. This is the subtle one and it came out of a real run: order total thirty-eight pounds, threshold fifty, and the gate fired. Several people will call that a bug. It was not — the model had composed a refund plus goodwill, and the amount being committed crossed the threshold. A gate reading the "real" number from the database would have let a larger payment through unapproved. Don't give an agent a tool you would not let it call unattended at 3am. That reframes tool design as a risk decision rather than a capability decision, which is the frame Session 5 builds on with Unity Catalog grants. Don't let a tool return a raw result set. It is the failure that does not look like a failure — no error, just a slow, expensive, confused agent. Likely question: "Is the double-write of the rule not duplication?" It is, and it is the good kind: two different audiences. The prompt explains, the code enforces. Keep them next to each other in the file so they drift together. Timing: 4 minutes, then break.
