Notebook gotcha

On serverless, cell 0 is %pip install -q openai then dbutils.library.restartPython(). Without it: ModuleNotFoundError.

This is the first notebook. Everyone runs the same three cells and sees the same output, which makes it a good place to sort out environment problems. The gotcha is on the slide because it caught us on every notebook in this course. Serverless compute does not have the OpenAI client pre-installed, and installing it mid-notebook requires restarting the Python process. The first cell of every lab notebook does both. If someone skips it, the error is ModuleNotFoundError on a line that looks fine. Walk the output, not the code. Two steps: the model asked for the tool, got a dict back, and wrote a sentence. Point out that nothing in the code parsed "ORD-1042" out of the question — the model read the parameter description, saw the example format, and composed the argument. Then set the "try this" exercise going, because it makes the previous slide's argument experiential rather than theoretical. Degrading the description to "order record lookup" reliably breaks tool selection on delivery questions. It is a satisfying thing to watch and it stays with people. Likely question: "Why the OpenAI client against Databricks?" Foundation Models are OpenAI-compatible, so the same client works and your agent code stays portable.
