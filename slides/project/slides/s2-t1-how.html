How a tool call travels

1 · Schemas sent

every tool's name, description and parameters go in the request

2 · Model selects

picks a tool and composes arguments from the conversation

3 · Your loop decides

validate, gate, or refuse — nothing has run yet

4 · Function runs

ordinary Python, no model involved

5 · Result appended

as a tool message, keyed to the call id

# what the model returns at step 2
tc.function.name      "get_order_status"
tc.function.arguments '{"order_id":"ORD-1042"}'
tc.id               "call_abc123"

Arguments arrive as a string

It is JSON text, not a dict. You json.loads it — and it can be malformed, because a model wrote it. Parse defensively.

The call id is not decoration

Your tool message must carry the same tool_call_id. Mismatch it and the model cannot tell which answer belongs to which question.

Multiple calls per turn

Step 2 can return several tool calls at once. Iterate over all of them and append all the results before looping.

This is the mechanics slide. Keep it brisk — the audience needs to recognise these objects when they see them in the notebook, not memorise them. Two details cause most first-time bugs, and both are on the slide. Arguments come back as a JSON string, not a parsed object. Everyone writes args["order_id"] on the raw value once. And because a language model produced that string, it can be malformed — rare with current models, not impossible. Wrap the parse and treat a failure as a tool error you report back, not a crash. The tool_call_id is the other one. Each result message must reference the id of the call it answers. If you issue two calls in a turn and get the ids wrong, the model receives the right data attached to the wrong question, and the failure is baffling because nothing errored. Point at step 3 again. This is the second time the deck has put a box between the model's decision and execution, and it will not be the last — Session 5 moves that box into the permission system entirely. Likely question: "Can I stream while tools are being called?" Yes, but the tool-call arguments stream as fragments you must accumulate. Get the non-streaming loop right first. Timing: 3 minutes.
