What is tool validation and error handling?

Three defences around every tool call: validate the arguments the model composed, handle the failure when the call goes wrong, and report it back in a form the model can act on.

Validate

Types from the signature; business constraints in code. A UC function validates types for you.

Classify the failure

Transient (retry) versus permanent (do not). A timeout is not a ValueError.

Report, don't crash

Return a tool message describing the failure. The model can ask the user or try another route.

Approve

For irreversible actions, the gate from Session 1 — on the argument, before execution.

A failure the model can read is a feature

“No order found with id ORD-9999” lets the agent ask the user to check the number. An exception ends the conversation with a stack trace.

The analogy

A form that says which field is wrong, rather than one that refuses to submit. The model is the user filling in the form.

This is an outline bullet the deck covered only in passing, and it is where agents feel robust or brittle in production. The framing that makes it click is in the white panel: a well-formed failure is a feature, not an error path. If the tool returns "no order found with id ORD-9999", the agent can tell the customer their reference looks wrong and ask them to check. If it raises, the conversation ends in a stack trace. Same underlying condition, two completely different user experiences, and the difference is a return statement. On classification: distinguishing transient from permanent failures is the single most valuable thing in the retry logic. A timeout deserves another attempt. Malformed arguments will fail identically the second time, so retrying spends money to be wrong twice — and the real fix is usually a clearer parameter description, which is Session 2. The validation card has a platform note worth landing. A Unity Catalog function validates types at the engine, so a whole class of argument error never reaches your code. Business constraints — thresholds, state machines, entitlements — still need to be explicit. Likely question: "Should validation errors go back to the model or to the user?" To the model, as a tool message. It will usually produce a better explanation for the user than your error string would. Timing: 3 minutes.
