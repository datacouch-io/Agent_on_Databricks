What is Unity Gateway?

Unity Gateway governs and monitors access to models, agents and tools: usage tracking, payload logging, rate limits and security controls, enforced centrally rather than per application.

A coding agent authenticates through Databricks Unified Auth and passes the request on the user's behalf to Unity Gateway, which authorises it against Unity Catalog and routes it to internal MCP tools — such as DBSQL and Genie — and to external MCP servers and LLM providers.
Source: docs.databricks.com/aws/en/ai-gateway/ai-governance

Say that once so nobody loses ten minutes looking for it. The diagram is the clearest statement of what it does and it is worth reading aloud, because the shape is the point. A request comes from an application — here a coding agent — authenticated as the user. It goes to the gateway, which authorises it against Unity Catalog and then routes it: to internal MCP tools like DBSQL and Genie, to external MCP servers, or out to another LLM provider. One governed choke point in front of all of it. The five capabilities are what you get for having that choke point. Usage tracking per user and per application is the one finance asks for. Payload logging into tables you own is the one audit asks for. Rate limits are the one you will want the first time an agent loops. Guardrails and routing complete the set. The connection to make for this room: Session 1 bounded one agent's loop with MAX_STEPS. The gateway bounds everything, including applications you did not write.
