Why split an agent — and why usually not yet

Good reasons to split

Tool count. Selection degrades past a few dozen tools.
Different identities. A worker that may issue refunds, one that may not.
Different owners. Two teams shipping independently.
Different models. A cheap worker for classification, a strong one for reasoning.

What goes wrong when you split too early

Latency multiplies, cost multiplies, and you add a failure mode that did not exist: the supervisor routes correctly and passes incomplete context, so a worker answers a question it was never equipped to answer — fluently.

Cost

Two loops instead of one. Every hop is a model call you pay for.

Latency

Sequential hops add up, and users feel each one.

Debugging

A wrong answer could be routing, context, or the worker. Traces become essential.

Real scenario

A supervisor routes a returns question to the policy worker and passes the question but not the order date. The worker quotes the 30-day window accurately and cannot apply it. The answer is correct, unhelpful, and nothing in the system reports an error.

Default to one agent with good tools. Split when you can name which of the four reasons applies.

This is Session 1's decision test again, one level up, and the same bias applies: multi-agent sounds more sophisticated, so people reach for it before they need it. Give the four good reasons as a checklist people can actually apply. Tool count is the measurable one — if tool selection is degrading past a few dozen tools, splitting genuinely helps. Different identities is the strongest one and ties to Session 5: a worker that may issue refunds and one that may not is a clean, enforceable boundary. Different owners is an organisational reason and a legitimate one. Different models is a cost argument. Then the scenario, which is the failure that justifies the whole slide. The routing was right. The worker was right. The answer was wrong, because the supervisor passed the question and not the order date, and the worker has no way to know a fact is missing. Nothing errors, no status is non-OK, and your dashboard is green. Say explicitly that this failure mode does not exist in a single agent, because all the context is in one messages list. You are trading it for the benefits above, so make sure you are getting them. Likely question: "How do I prevent context loss?" Make the supervisor's handoff explicit and traced, and give workers the ability to ask for what they are missing rather than answering regardless. Timing: 4 minutes.
