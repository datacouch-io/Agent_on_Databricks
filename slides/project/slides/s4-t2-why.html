Why an uncurated space is confidently wrong

What goes wrong without curation

The model sees column names and types. It does not know that status has a value meaning the order never happened, that your fiscal year starts in April, that customers contains test accounts, or which of two date columns means “when it shipped”. It will make a choice on each, and the SQL will run.

The engineering value

Every instruction and example you add is a defect class removed permanently, for every caller, measurable by a benchmark run before and after.

Instructions

Prose rules. Best for filters, exclusions and definitions: “revenue excludes cancelled”.

Examples

Question plus the SQL you would have written. Best for joins, grains and date conventions.

Knowledge mining

Genie proposes both from your query history. A draft to review, not an authority.

Real scenario

An organisation whose fiscal year starts in April asked for “Q1 revenue”. No prose instruction reliably fixed it. One worked example — the question, and the SQL with the right date boundaries — did, immediately and for every similar question afterwards.

The division is practical: instructions for rules, examples for shapes. If it involves a join or a date convention, write the query.

Prose is poor at shapes, because describing a three-table join in English and hoping the model reconstructs it is worse than just writing the join.
