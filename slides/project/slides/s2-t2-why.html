Why the seam outlives whatever you choose today

What goes wrong without it

Vendor calls spread through the agent — in the loop, in the prompt builder, in the tool handlers. Changing retriever becomes a rewrite, so you never evaluate an alternative, so you never find out whether the one you picked is any good.

The engineering value

A seam makes the experiment cheap. One constructor argument and you have a controlled comparison: same agent, same questions, one component different.

Develop without infrastructure

The dictionary retriever needs no endpoint, no index, no warehouse. Tests run in milliseconds.

Compare honestly

A result with no baseline is not a result. The cheap retriever is your control.

Survive the roadmap

This field reorganises every few months. The seam is the part of your code that does not care.

Real scenario

Every notebook in this course runs the same core.py. It was written before the AI Search index existed, survived a move from local Python to serverless notebooks, and is the file that did not change when Session 7 introduced a framework and a managed assistant.

The seam is worth more than either retriever — it is what lets you run the next comparison, against a product that has not shipped yet.
