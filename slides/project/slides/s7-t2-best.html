Building it yourself versus a managed assistant

Build your own agent when

• A control must sit at query time — audience filters, tenancy, entitlements
• The flow is more than retrieve-and-answer
• You need tools that take actions, with gates
• It must live in CI, with versions and rollback
• You need to inspect and tune retrieval

Use a managed assistant when

• The task really is QA over a document set
• You want a quality signal without building an evaluation set first
• Time to something usable matters more than control
• The corpus has one audience, or is split by grants
• Nobody on the team wants to own retrieval tuning

Not a hierarchy

A managed assistant is a legitimate production answer for the right corpus.

A good baseline

Even when you build your own, it is a credible control to measure yourself against.

The decision that matters

Where must your controls live? If the answer is “at query time, under my control”, build it. If the answer is “in the grants”, a managed assistant is fine.

This is the outline's "Agent Framework versus Agent Bricks" bullet, and it should be a decision aid rather than a verdict. Work both columns honestly. The right-hand column is not a list of compromises — for genuine QA over a document set with one audience, a managed assistant is a good production answer, and insisting on building it yourself is how teams spend a quarter reproducing something they could have had on Tuesday. The left-hand column is where control is the requirement. The first bullet is the one Lab 7B demonstrates and it is the decisive one: if a control has to apply at query time, inside the retrieval call, you need to own the retrieval call. The bottom bar reduces the whole decision to one question, and it is the question this course has been teaching people to ask since Session 1: where must your controls live? If they can live in grants — split the corpus, grant per audience — the managed route is fine. If they must live at query time, build it. That reframing is more useful than any feature comparison, and it will still be right when the product list changes. Likely question: "Can we start managed and migrate later?" You can start managed and build alongside it, using the managed one as your baseline. You cannot export it, so plan it as a parallel build rather than a migration. Timing: 4 minutes.
