Three cells and it is the most convincing thing in the session. Run it as the full principal, print the list, then change one variable — the token — and print again. Three tools become two. Nothing else in the notebook moved. The white panel is the line to repeat. The agent did not decide what it could do. It asked, and the platform answered based on grants. That is the inversion this whole session has been building toward: capability is a property of the identity, not of the code. Set the "try this" exercise going, because it makes the point in the opposite direction. Revoking a grant narrows a running agent's abilities with no deployment, no restart and no code review. For an incident response that is an extremely useful property — you can take a capability away from every client at once. If anyone asks why we use raw requests rather than an MCP client library: the lab wants the wire protocol visible. In production use a client library; here, seeing tools/list return two entries instead of three is the lesson. Likely question: "Does the model get told a tool was withheld?" No. It is absent from the list, so the model has no knowledge of it. That is the design, and it is stronger than a refusal. Timing: 10 minutes of lab, 3 minutes on this slide.
