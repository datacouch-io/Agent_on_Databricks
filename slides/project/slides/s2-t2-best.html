Keeping the seam honest — do and don't

Do

Return a fixed shape — {doc_id, text, score} — and convert inside each retriever.

Keep a no-infrastructure retriever for tests and as an experimental control.

Enforce the boundary with a check, not a convention. The lab asserts on core.py's imports.

Pass the retriever in at construction. Never import one inside the loop.

Put filters and ranking tweaks in the retriever, where the next caller inherits them.

Don't

Don't leak vendor parameters through the signature just because one backend needs them.

Don't let the agent branch on which retriever it has. That is the seam failing.

Don't grep for vendor names as your only check — ours matched a docstring and cried leak.

Don't duplicate retrieval logic in a tool handler “just for this one case”.

Don't assume a control in the caller travels. Session 7 proves it does not.

The third pair is a real finding. Our portability check was a grep for “databricks” in core.py, and it reported a leak — the match was the docstring saying the file must not import Databricks. We replaced it with an AST import check and kept the grep, labelled as a known false positive.

Close the topic with the practices, and use the callout rather than reading the lists. The grep story earns its place because it is the course's running theme appearing early and harmlessly. We wrote an automated check, it reported a failure, and the failure was in the check. Had we trusted it, we would have gone looking for an import that was never there. The lesson generalises past this one bug: when a check fails, read what it actually matched before you read what it claims. By Session 6 the same mistake costs a day of chasing a model regression that never happened. On the last pair, plant the flag for Session 7: a filter you apply in the caller protects your calls and nobody else's. Where a control lives decides who inherits it, and that sentence returns three more times in this course. The second "don't" is the one to watch for in your own code. The moment the agent asks "which retriever do I have?", the abstraction has stopped paying for itself and you have two code paths pretending to be one. Likely question: "What if one backend needs a parameter the others cannot use?" Give the retriever its own constructor argument and keep the call signature fixed. Configuration belongs to the implementation, not to the contract. Timing: 3 minutes.
