What the trace shows

Two spans, both OK. The routing span is correct. The handoff span is where the order date should be and is not. You cannot see this in the final answer alone.

Fix it two ways

Either the supervisor fetches the order first and includes the date in the handoff, or the policy worker is given the order tool so it can ask. Compare the cost of each.

Run both and let run two stand without resolving it immediately. The answer is accurate, well-written and does not help the customer, and that combination is the thing to sit with. Then open the trace. Both spans are OK. Nothing failed. The routing decision was right — a returns question is a policy question. The defect is in the handoff payload, which contains the question and not the order date, and the worker had no way to know a fact was missing. Connect it back to Session 3's closing note: every span OK, every tool successful, and the answer wrong. Span status measures plumbing. Then work the two fixes as a design discussion, because there is no single right answer. The supervisor fetching the order first is cheaper — one extra tool call — and makes the supervisor know about orders, which erodes the separation you split for. Giving the policy worker the order tool keeps the supervisor thin and widens the worker's tool set and its permissions. Ask the room which they would choose and why; both answers are defensible and the reasoning is the lesson. Likely question: "Would a single agent have got this right?" In this case yes, because all the context sits in one messages list. That is the honest cost of splitting, and it is why the previous slide said default to one.
