This is the slide to slow down on. It is five lines of code and it carries the single most important idea in Session 1. Lab 1B ships with the rule in two places — once in the system prompt, once in needs_human(). Delete the code gate, keep the prompt, and run the compensation request several times. It usually holds. Usually is the problem: you cannot write a test for usually, and you cannot explain usually to a risk committee. Then the subtler half. Walk the audience through the arithmetic out loud: order total 38, threshold 50, gate fires. Someone will say it is a bug. It is not. The model proposed 38 for the refund plus goodwill on top, and the amount in args crossed 50. Had we gated on the order total from the database — the "real" number — the larger payment would have gone through unapproved. The rule to take away: gate on the value being committed, not on the value you expect it to be derived from. Expected question: "Should the model know the gate exists?" Yes — tell it in the prompt so it can explain the refusal to the customer. Just never rely on the prompt to enforce it. Timing: 6 minutes. Do not rush this one.
