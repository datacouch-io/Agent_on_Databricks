Catalog functions as tools — do and don't

Do

Write the COMMENT as prompt text. Say what it does and what it returns; review it like code.

Give every parameter an example value in its comment. Malformed arguments largely stop.

Grant to the application ID, never the display name.

Use definer's rights deliberately — grant EXECUTE on the function, not SELECT on the table.

Return a narrow, decided result. One row, named columns, no SELECT *.

Keep the DDL in version control and apply it through a migration, not by hand.

Don't

Don't put the permission check in your agent loop when the platform can enforce it.

Don't write “gets data” as a comment and then blame the model for picking the wrong tool.

Don't expose a function that returns an unbounded result set. It becomes the next prompt.

Don't grant to a group without checking who is in it today and who can add to it.

Don't edit a COMMENT casually. You are editing the model's instructions.

Don't register a destructive action without a gate in front of it as well.

The last pair is Session 1 and Session 5 meeting. A GRANT decides whether an identity may call issue_refund. It does not decide how much. Amount thresholds are still a code gate on the argument — governance and gating solve different problems.

The callout is the most useful thing on this slide, because it prevents a tempting mistake. People leave Session 5 inclined to move every control into Unity Catalog. Grants are an excellent answer to "may this identity do this at all" and no answer at all to "may it do this for one hundred and twenty pounds". A grant is binary and static; the refund threshold is a predicate over an argument the model just composed. You need both, and they sit in different places: the grant at the platform, the threshold in the loop. Two other lines worth saying. "Don't edit a COMMENT casually" catches teams off guard — a comment change is a prompt change and it alters tool-selection behaviour, with no code diff in the agent repository to show for it. Put the DDL in version control so that edit is reviewable. "Don't grant to a group without checking who can add to it" is the permission question people skip. The membership list today is less important than who controls it tomorrow. Likely question: "Should every tool be a catalog function?" Anything touching governed data, yes. A pure utility with no data access — a date formatter — is fine as plain code, and registering it buys nothing. Timing: 3 minutes.
