Why an OpenAI-compatible endpoint is a strategic detail

What goes wrong with a proprietary client

Agent code written against a vendor-specific SDK is married to that vendor. Model choice stops being an experiment and becomes a migration, so you stop running the experiment.

The engineering value

The model becomes a configuration value. That is what makes champion-versus-challenger testing, cost-down exercises and emergency provider switches ordinary operations rather than projects.

Portability

The same core.py runs against Databricks, against a local model, or against a provider's own API.

Ecosystem

Every tool, framework and tutorial written for the OpenAI format works unmodified.

Negotiation

A stack you can leave is a stack you can get a better price on.

Real scenario

Session 6 compares two prompt variants and two models over the same evaluation dataset. The only lines that differ between runs are a model name and a system prompt. Had the client been proprietary, that comparison would have been a rewrite rather than a parameter sweep.

Keep the model name in configuration, never inline. The cost of inlining it is not visible until the day you need to change it in a hurry.
