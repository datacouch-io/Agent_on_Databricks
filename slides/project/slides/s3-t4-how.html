How a trace becomes a table you can query

1 · Decorate

@mlflow.trace with a span_type

2 · Set destination

UnityCatalog(catalog, schema)

3 · Run the agent

spans written asynchronously

4 · Two tables appear

traces, and trace_spans

5 · Query

SQL over spans, filtered by type

SELECT span_type,
       count(*) AS calls,
       avg(execution_duration) AS avg_ms,
       sum(CASE WHEN status.code <> 'OK'
            THEN 1 ELSE 0 END) AS failures
FROM cat.sch.mlflow_experiment_trace_spans
GROUP BY span_type

The gotcha everyone hits

It is status.code, not status_code. These are OpenTelemetry spans, so status is a struct. The obvious query fails with UNRESOLVED_COLUMN and the column list does not make the fix obvious.

The UI is for one interaction

Nested spans, arguments, retrieved chunks. Perfect for a single bug report.

The table is for a thousand

Aggregates, trends, and the join to your own business tables.

Show the UI first in the room — it is immediately legible and it earns attention — then move to the SQL, because that is the part people do not expect to exist. The query on the slide is the one to run on day one of any agent in production: calls, average duration and failures, grouped by span type. It answers "what is slow" and "what is erroring" in a single pass, and it needs no custom instrumentation beyond the decorators. Spend the thirty seconds on the gotcha. Everybody writes status_code, because every logging system they have used calls it that. These spans are OpenTelemetry, so status is a struct with a code field. The error — UNRESOLVED_COLUMN — does not suggest the fix, and the schema is wide enough that scanning it is slow going. Cheaper to hear it here. Make the division of labour explicit at the end: the UI answers "what happened in this interaction", the table answers "what is true of this system". You need both, and teams usually only build the first. Likely question: "Can I join traces to business data?" Yes, and that is where the real value is — join span data to tickets, refunds or conversions, and you can measure whether the agent affected outcomes rather than just scores. Timing: 4 minutes.
