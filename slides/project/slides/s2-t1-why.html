Why your tool descriptions are the agent's real prompt

What goes wrong without good descriptions

The model picks the wrong tool, or invents arguments that look plausible and are not. Both failures look like model stupidity in a demo and turn out to be a one-line description doing no work.

The engineering value

Tool selection is the cheapest place to improve an agent. Rewriting a description costs nothing, ships instantly, and needs no retraining, no fine-tuning and no new infrastructure.

Too vague

“Gets order data.” → model calls it for questions about shipping policy.

Too narrow

“Use only for delivered orders.” → model refuses to look up a pending one.

About right

“Look up one order by its id. Returns status, total and date.”

Real scenario

An agent with get_order_status and search_policy was asked “where is my parcel?” and searched the policy documents. The order tool's description said “order record lookup”. Changing it to mention status and delivery fixed the behaviour with no code change.

Argument descriptions matter just as much. Give an example value — 'Order id, e.g. ORD-1042' — and malformed arguments largely stop happening.
